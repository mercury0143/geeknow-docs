# MiniMax H3 视频

MiniMax H3 在 Geeknow 中通过统一的视频网关异步生成视频。开发者只需要使用公开的 `/v1/videos` 路由；上游 DMC 的 `/v2/video_generation` 和 `/v2/query/video_generation/{task_id}` 属于服务内部链路，不应直接写入客户端。

| 操作 | 方法与路径 |
| --- | --- |
| 创建任务 | `POST /v1/videos` |
| 查询任务 | `GET /v1/videos/{task_id}` |
| 代理下载 | `GET /v1/videos/{task_id}/content` |

## 能力与固定规格

请求体使用上游 H3 的 `content[]` 结构：一个文本项可以组合首帧、尾帧、参考图片、参考视频和参考音频。

| 项目 | 规则 |
| --- | --- |
| 模型 | `MiniMax-H3`。插件也兼容 `minimax-h3`、`minimax-h3-pro` 等历史模型名，但最终都会归一到 H3 单一入口 |
| 输出清晰度 | 固定 `768P`；不提供 `2K` |
| 输出时长 | `duration` 为整数，`1` 到 `15` 秒 |
| 画幅 | `21:9`、`16:9`、`4:3`、`1:1`、`3:4`、`9:16` |
| 输出格式 | MP4、H.264、24 FPS；AAC、32 kHz、双声道 |
| 请求格式 | `application/json` |
| 鉴权 | `Authorization: Bearer YOUR_API_KEY` |
| 音频 | H3 原生生成有声视频，插件会强制启用音频 |

`adaptive` 是上游能力的一部分，但当前 Geeknow 插件适配层只提交固定画幅；未传或不支持的比例会回退为 `16:9`。传入历史 2K 模型名也不会得到 2K，最终输出仍是 `768P`。

## 支持的生成方式

| 生成方式 | `content[]` 组成 | 说明 |
| --- | --- | --- |
| 文生视频 | 一个 `text` 项 | 不携带媒体项 |
| 首帧生视频 | `text` + 一个 `image_url`，`role: "first_frame"` | 用输入图片约束起始画面 |
| 尾帧生视频 | `text` + 一个 `image_url`，`role: "last_frame"` | 用输入图片约束结束画面 |
| 首尾帧 | `text` + `first_frame` + `last_frame` | 首尾帧不能和 `reference_*` 角色混用 |
| 参考素材视频 | `text` + 一个或多个 `reference_*` 项 | 可组合参考图片、参考视频和参考音频 |

## 媒体约束

所有媒体必须是服务端可以直接访问的公网 HTTPS URL。不要提交 Base64、data URI、`mm_file://`、本地路径、私网地址或回环地址。插件收到本地图片时会先上传为 HTTPS URL，再提交给网关。

| 媒体 | `type` | 可用 `role` | 数量 | 单文件上限 |
| --- | --- | --- | ---: | ---: |
| 图片 | `image_url` | `first_frame`、`last_frame`、`reference_image` | 最多 9 张 | 30 MB |
| 视频 | `video_url` | `reference_video` | 最多 3 段 | 50 MB |
| 音频 | `audio_url` | `reference_audio` | 最多 3 段 | 15 MB |

全部媒体项合计最多 12 个。参考视频和参考音频每段至少 2 秒，超过 15 秒时只保留开头 15 秒；裁切后的参考视频总时长和独立参考音频总时长分别不能超过 15 秒。图片应为静态 JPG/JPEG、PNG、WebP、HEIC 或 HEIF。

参考素材应在提示词中按出现顺序使用 `<Picture 1>`、`<Video 1>` 和 `<Audio 1>` 等标签指代。一个请求必须且只能有一个非空文本项，文本最多 7000 个 Unicode 字符。

## 任务生命周期

创建成功只代表任务已受理。服务可能在 `queued` 阶段下载、探测、转码和审核输入，之后才开始生成。

| 状态 | 含义 |
| --- | --- |
| `queued` | 已受理，正在准备输入或等待生成 |
| `running` | 正在生成或发布结果 |
| `succeeded` | 视频已生成并发布结果地址 |
| `failed` | 输入准备、审核或生成失败 |
| `cancelled` | 服务端终止任务 |

输入下载、媒体格式、内容审核和服务繁忙等问题可能在创建返回 `task_id` 后才以 `failed` 表示。查询失败任务通常仍返回 HTTP `200`，请读取 `task.error`。

## 结果与计费

成功任务的结果地址应直接使用查询响应返回的完整 URL，不要根据 `task_id` 拼接地址。公开结果地址可能在服务清理后失效；需要长期保存时，请在任务成功后尽快下载到自己的存储。查询接口仍需 Bearer 鉴权，返回的公开结果 URL 下载时不要附带该鉴权头；如果直链不可用，可以使用带鉴权的 `/content` 代理端点。

当前用量按客户提交的输出 `duration` 统计，关键帧和参考素材不会改变输出秒数计费口径。正式单价、额度和账单以账户后台为准。

## 明确不提供

- `2K` 输出；
- `adaptive` 画幅透传；
- 提示词增强、视频再生成、任务列表筛选和公开取消接口；
- Base64、data URI、动态图片和自定义推理参数；
- SSE 或本页未列出的 MiniMax 官方接口。
