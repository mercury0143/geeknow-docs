# MiniMax H3 视频

MiniMax H3 按秒计费版本使用 `POST /v1/videos` 创建异步视频任务，使用 `GET /v1/videos/{task_id}` 查询状态，并可通过 `GET /v1/videos/{task_id}/content` 下载生成结果。

当前项目的 H3 接入不是一个抽象模型，而是两个真实模型：`minimax-h3-768p` 和 `minimax-h3-2k`。它们的请求字段、生成模式和参考素材规则一致，主要差异在输出清晰度和推荐使用场景。

## 先选模型

| 实际模型 | 清晰度 | 参考规格 | 计费口径 | 适合场景 | 接入建议 |
| --- | --- | --- | --- | --- | --- |
| `minimax-h3-768p` | 768P | `503`：最多 5 张参考图、0 段参考视频、3 段参考音频 | 按输出秒数计费 | 草稿预览、批量生成、移动端分发、常规清晰度任务 | 默认优先使用这一档；没有明确高清交付要求时，不建议默认使用 2K |
| `minimax-h3-2k` | 2K | `503`：最多 5 张参考图、0 段参考视频、3 段参考音频 | 按输出秒数计费 | 成片交付、大屏展示、需要保留更多画面细节或后期裁切的任务 | 在确认要高清输出时使用；2K 任务生成耗时也可能更长 |

<Warning>
  `768P` 和 `2K` 不是两个不同的功能集。两者都支持文生视频、图生视频、首尾帧、参考图和参考音频；选择 2K 是对输出清晰度的选择，不会自动改善提示词、动作设计或低质量参考图本身。
</Warning>

## 入口映射

直接调用 API 时，推荐把 `model` 写成真实模型名：`minimax-h3-768p` 或 `minimax-h3-2k`。

前端插件为了简化配置，会展示一个单入口 `minimax-h3`。后端适配层会根据 `resolution`、`video_resolution` 或 `size` 自动分流：

1. 清晰度是 `2K` 或字段值包含 `2160` 时，实际模型使用 `minimax-h3-2k`。
2. 其他情况默认使用 `minimax-h3-768p`。
3. 如果调用方已经直接传 `minimax-h3-768p` 或 `minimax-h3-2k`，适配层会保留该模型名。

## 支持能力

| 能力 | 字段 | 说明 |
| --- | --- | --- |
| 文生视频 | `prompt` | 只传文本提示词，不需要参考素材 |
| 图生视频 | `referenceImages` | 传 1 张参考图时常用于首帧图生视频 |
| 多参考图 | `referenceImages` | 最多 5 张，适合角色、主体、风格或场景参考 |
| 首尾帧 | `first_image`、`last_image` | 用首帧和尾帧约束视频起止画面；不要同时传 `referenceImages` |
| 参考音频 | `referenceAudios` | 最多 3 段公网音频 URL，合计建议不超过 15 秒；需要搭配至少 1 张 `referenceImages` |

## 接口约定

| 项目 | 规则 |
| --- | --- |
| 创建任务 | `POST /v1/videos` |
| 查询任务 | `GET /v1/videos/{task_id}` |
| 下载内容 | `GET /v1/videos/{task_id}/content` |
| 请求格式 | `application/json` |
| 鉴权方式 | `Authorization: Bearer YOUR_API_KEY` |
| 时长字段 | `duration`，整数秒，范围 `4` 到 `15` |
| 画幅字段 | `ratio`，支持 `16:9`、`9:16`、`1:1`、`21:9`、`4:3`、`3:4` |
| 清晰度字段 | `resolution`、`video_resolution` 或 `size`，支持 `768P` 和 `2K` |
| 参考规格 | `503`，表示 5 张参考图、0 段参考视频、3 段参考音频 |

## 当前边界

- 当前项目只文档化 `minimax-h3-768p` 和 `minimax-h3-2k` 两个按秒计费模型。
- 当前项目 H3 适配层不透出 `adaptive` 画幅；如果传入不支持的比例，会回退为 `16:9`。
- 当前项目不把 `minimax-h3-pro-*` 作为已接入能力写入本页。需要参考视频驱动时，需要先确认服务端是否另行开放 Pro 档。
